## 3. Recommended Test Setup Approach

### Recommended Approach: FastAPI `TestClient` with Fixture-Based DB Isolation
1. **In-Process FastAPI Execution (`fastapi.testclient.TestClient`)**:
   - Direct importing of `app.main:app` in pytest test files.
   - Fast, deterministic execution without network overhead, port binding conflicts, or subprocess management.
2. **Database Isolation Strategy**:
   - Use pytest fixtures (`@pytest.fixture`) to override FastAPI's `get_db` dependency (`app.dependency_overrides[get_db] = override_get_db`).
   - Create isolated SQLite test databases per test module or test session (using temporary files via `tmp_path` or `sqlite:///:memory:`).
   - Pre-seed standard test data (roles, cashier accounts, test products) in fixture setup and clean up tables post-test.
3. **Dual-Mode Client Support**:
   - Abstract client creation in a fixture (`api_client`) that defaults to `TestClient(app)`, but can switch to an external HTTP client (`httpx.Client` / `requests`) targeting `http://127.0.0.1:8000` if `TEST_BASE_URL` environment variable is supplied.
4. **Test Runner Script**:
   - `/home/xasanboy/ERP/run_e2e_tests.sh` invoking `/home/xasanboy/ERP/Back/venv/bin/pytest tests/e2e/test_mobile_pos_e2e.py -v --tb=short`.

## 5. Logic Chain

1. **Observation**: Backend codebase is located in `/home/xasanboy/ERP/Back` using FastAPI and SQLAlchemy with SQLite.
2. **Observation**: Virtual environment `/home/xasanboy/ERP/Back/venv` contains Python 3.12, `pytest` 9.1.1, `requests` 2.34.2, `fastapi` 0.139.0, and `httpx` 0.28.1.
3. **Reasoning**: `FastAPI TestClient` provides direct, in-memory route invocation without launching a background server process.
4. **Deduction**: Combining `TestClient` with SQLAlchemy database dependency overriding allows isolation between tests, eliminating flaky state pollution in `erp.db`.
5. **Conclusion**: The recommended approach for Milestone 1 E2E tests is an in-process `pytest` suite using `TestClient(app)` backed by isolated SQLite database fixtures.
